서비스 소개

왜 만들었는지, 누구를 위해 만드는지, 그리고 이 서비스가 무엇을 하지 못 하는지까지 솔직하게 정리했습니다.

목적과 타겟

해결하려는 문제

채용 공고는 여러 사이트에 흩어져 있고, 같은 공고가 중복되며, 급여가 없거나 조건이 모호한 경우도 많습니다. 구직자는 "내가 이 공고에 맞는 걸까?"를 매번 스스로 판단해야 합니다.

핵심 사용자

이직을 준비하는 개발자·디자이너·PM 등 원격 근무를 선호하는 전문직 구직자. 특히 공고를 많이 볼 시간이 없거나, 첫 스크리닝을 어디서부터 해야 할지 모르는 사람을 대상으로 합니다.

제외하는 대상

국내 채용 사이트(사람인·잡코리아 등)의 로컬 공고, 구인 등록이 필요한 경우, 그리고 "누구에게나 적용되는 일반 잡 cowork 안내"는 다루지 않습니다.

페이지 구성

AI 기능 정의

입력 · 처리 · 출력 · 실패 처리를 명확히 분리했습니다.

입력

  • 희망 직무 (필수)
  • 기술스택 (필수, 쉼표 구분)
  • 경력 수준 (선택)
  • 최소 희망 금여 (선택)
  • 자기소개 서술 (선택)

출력

  • 공고별 적합도 점수 (0~100)
  • 매칭 근거 최대 3개
  • 아쉬운 점 (조건 불일치)
  • 다음에 할 행동 제안
  • 공고 출처 · 원문 링크

처리 순서

  1. 입력 검증
  2. 공고 수집 (캐시 10분)
  3. 키워드 사전 매칭 → 후보 8건
  4. AI 판정 (JSON 출력 강제)
  5. 점수순 정렬 후 렌더링

실패 처리 기준

사용자에게 항상 무엇이 왜 안 됐는지 알려줍니다.

상황HTTP사용자에게 보여주는 것
필수값 미입력 400 어느 칸이 비었는지 안내 + 해당 칸 빨간 테두리
조건이 너무 좁아 결과 0건 404 "기술스택을 더 일반적인 단어로 적어보라"는 안내
원천 서버 3곳 모두 실패 503 "잠시 후 다시 시도" 안내 (빈 화면 대신)
AI 키 미설정 / 호출 실패 200 경고 배지 "코드 분석으로 대체됨" + 키워드 점수로 결과 제공
응답 지연 (45초 초과) — AbortController 로 요청 중단 후 타임아웃 안내
네트워크 단절 — "네트워크 상태를 확인해 주세요" 안내

기술적 한계 (솔직하게)

캐시는 휘발성

Vercel Serverless Functions의 메모리 캐시는 인스턴스 종료 시 사라집니다. 즉 "정확히 10분마다 갱신"이 아니라 "인스턴스가 살아 있는 동안 재사용"입니다.

국내 공고 미포함

사용한 3개 API는 모두 해외 원격 공고 중심입니다. 국내 공고를 넣으려면 사람인/잡코리아 API 승인 절차를 별도로 거쳐야 합니다.

점수는 참고용

추천 결과는 실제 적합도를 보증하지 않습니다. 실제 지원 가능 여부는 공고 원문과 채용 담당자의 판단이 우선입니다.
