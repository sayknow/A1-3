## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | **JobFit** |
| 배포 주소 | **https://jobfit-seven.vercel.app** (Vercel Hobby, Vercel Serverless Functions) |
| 소스 저장소 | https://github.com/sayknow/A1-3 |
| 한 줄 정의 | 구직자의 조건을 입력하면 실제 원천 서버의 구인중인 공고 중 적합한 것을 AI가 골라 **근거와 함께** 추천하는 웹 서비스 |
| 해결하려는 문제 | 채용 공고가 여러 사이트에 흩어져 있고, 같은 공고가 중복되며, 급여·조건 정보가 모호해 첫 스크리닝에 시간이 오래 걸린다 |

## 2. 목적과 타겟 사용자

### 2.1 목적
1. 공고를 하나씩 열어보지 않고도 **스스로 걸러내는 시간**을 줄인다.
2. 추천 결과에 **이유**를 붙여, 왜 이 공고가 제시되었는지 사용자가 스스로 판단할 수 있게 한다.
3. 데이터 출처와 수집 시점을 **숨기지 않고** 표시해 신뢰를 만든다.

### 2.2 타겟 사용자 (1차)
- 이직을 준비 중인 **개발자·디자이너·PM 등 전문직 구직자**
- 원격(리모트) 근무를 선호하며 근무 지역에 제한이 없는 사람
- 공고가 많아 어디서부터 봐야 할지 모르는 사람

### 2.3 타겟 사용자 (2차 — 확장)
- 이직 준비 중인 신입·주니어
- 원격 공고를 모아 보고 싶은 경력자

### 2.4 명시적으로 다루지 않는 것
- 국내 채용 사이트(사람인·잡코리아·원티드)의 로컬 공고 — 해당 API는 승인·계약 절차가 필요해 이번 과제 범위에서 제외
- 구직자 계정·이력서 등록·지원 제출 등 커뮤니티 기능
- 온보딩/면접 코칭 등 추천 이후의 지원 워크플로

## 3. 페이지 구성 및 내비게이션

상단 고정 헤더의 내비게이션으로 4개 페이지 사이를 이동합니다. 모든 페이지가
`index.html` / `about.html` 로 이동 가능하며, 현재 위치는 `is-active` 클래스로 강조됩니다.

| # | 페이지 | 역할 | 백엔드 호출 |
| --- | --- | --- | --- |
| 1 | `index.html` (홈) | 서비스 소개, 사용 흐름 5단계, 데이터 출처 통계 | `GET /api/jobs` |
| 2 | `recommend.html` (AI 추천) | **핵심 기능.** 조건 입력 폼 → 추천 결과 | `POST /api/recommend` |
| 3 | `jobs.html` (공고 목록) | 전체 공고 탐색, 출처 필터, 키워드 검색, 정렬 | `GET /api/jobs` |
| 4 | `about.html` (서비스 소개) | 기획 요약, AI 기능 기준표, 실패 처리 기준, 한계 | 없음 (정적) |

**메뉴 이동 방식**
- 모든 페이지 상단에 동일한 내비게이션 배치
- 현재 페이지 자동 강조 (`markActiveNav()` — HTML 에 매번 클래스 없이 JS 로 처리)
- 768px 이하에서는 내비게이션이 두 번째 줄로 내려가며 4개 항목이 균등 분배

## 4. 데이터 흐름

```
[브라우저]                          [Vercel Serverless (Python)]
   │                                        │
   │  1. 폼 입력 + 제출                     │
   │  ───── POST /api/recommend ────────▶  │
   │                                        │ 2. 입력 검증
   │                                        │ 3. 원천 API 3곳 호출
   │                                        │    (키 불필요 공개 엔드포인트)
   │                                        │ 4. 필드 이름이 다르므로
   │                                        │    공통 형태로 정규화
   │                                        │ 5. 중복 제거 · 캐시 저장
   │                                        │ 6. 키워드 사전 매칭
   │                                        │    → 후보 8건으로 축소
   │                                        │ 7. AI 판정 (키 있을 때만)
   │  ◀──── JSON 응답 ──────────────────   │
   │                                        │
   │  8. fetch().then() 으로 받음             │
   │  9. 점수순 정렬 후 DOM 렌더링            │
```

### 4.1 데이터 출처 (모두 API 키 불필요)

| 출처 | 엔드포인트 | 특징 |
| --- | --- | --- |
| RemoteOK | `https://remoteok.com/api` | 글로벌 원격 IT 직군. 응답 첫 원소가 약관 메타데이터라 제외 필요 |
| Remotive | `https://remotive.com/api/remote-jobs` | 원격 직군 폭넓음. 급여가 문자열(`90k - 105k`)로 옴 |
| Arbeitnow | `https://www.arbeitnow.com/api/job-board-api` | 유럽 중심. 게시시각이 Unix 타임스탬프로 옴. IT 외 일반 고용 공고 혼재 |

세 곳 모두 이용 약관에 따라 화면 하단과 README에 출처를 명시합니다.

## 5. AI 기능 정의

### 5.1 이름
**"내 조건 맞춤 공고 추천"** — `POST /api/recommend`

### 5.2 입력

| 항목 | 필수 | 타입 | 설명 |
| --- | --- | --- | --- |
| `role` | 필수\* | string | 희망 직무 (프론트/백엔드/풀스택/ai/데이터/devops/모바일/qa) |
| `skills` | 필수\* | string | 기술스택, 쉼표 구분 (예: `python, docker, aws`) |
| `level` | 선택 | string | 경력 수준 (junior/mid/senior) |
| `min_salary` | 선택 | number | 최소 희망 연봉 |
| `summary` | 선택 | string | 자유 자기소개 (AI 프롬프트에 포함) |
| `top_n` | 선택 | number | 반환 개수 (기본 5, 최대 10) |

\* 직무와 기술스택 중 **하나 이상**은 반드시 입력해야 함.

### 5.3 출력

| 필드 | 설명 |
| --- | --- |
| `match_score` | 적합도 점수 0~100 |
| `reasons` | 매칭 근거 최대 3개 (키워드 일치 근거 또는 AI 작성) |
| `concern` | 아쉬운 점 (조건 불일치·미확인 사항) |
| `action` | 다음에 할 행동 제안 |
| `code_score` | AI 판정 전 코드 계산 점수 (비교용) |
| `ai_status` | `ok` / `failed` / `disabled` — 어떤 방식의 결과인지 투명하게 표시 |
| `total_jobs` / `candidate_count` | 분석 대상 전체 공고 수 / AI에 넘긴 후보 수 |

**점수 산식 (코드 사전 매칭 기준, 합계 100점)**
| 항목 | 배점 |
| --- | --- |
| 직무 연관성 | 최대 40 |
| 기술스택 일치율 | 최대 35 |
| 급여 선호 정합 | 최대 15 |
| 경력 수준 정합 | 최대 10 |
| 직군 적합도 보정 | +8 / −12 |

### 5.4 사용자에게 제공하는 가치
점수가 아무리 높게 나와도 **왜 추천됐는지, 무엇이 부족한지**를 함께 읽어야 판단할 수 있습니다.
그래서 근거·아쉬운 점·행동 제안을 함께 표시하고, 점수만 보고 판단하는 것을 유도하지 않습니다.

### 5.5 AI 호출이 비용을 아끼는 구조
공고 133건을 그대로 AI에 보내면 비싸고 느립니다.
1차 코드 매칭으로 **상위 8건만** AI에 전달하고(`AI_CANDIDATE_LIMIT`),
공고 설명도 600자로 잘라 넣습니다. AI 실패 시에는 1차 결과가 그대로 살아 있어
기능이 끊기지 않습니다.

### 5.6 실패 처리 기준

| 상황 | HTTP | 서버 응답 | 사용자 안내 |
| --- | --- | --- | --- |
| 필수값 미입력 | 400 | `{"error": "..."}` | "직무 또는 기술스택을 입력해주세요" + 해당 칸 빨간 테두리 |
| JSON 형식 오류 | 400 | `{"error": "..."}` | "요청 본문을 읽을 수 없습니다" |
| GET으로 호출 | 405 | `{"error": "..."}` | "POST 방식만 지원합니다" |
| 조건이 너무 좁아 0건 | 404 | `{"error": "..."}` | "기술스택을 더 일반적인 단어로 적어보세요" |
| 원천 API 3곳 모두 실패 | 503 | `{"error": "..."}` | "잠시 후 다시 시도해주세요" (빈 화면 아님) |
| AI 키 미설정 | 200 | `ai_status: "disabled"` | "AI 미연동 상태" 배지 + 코드 점수로 정상 제공 |
| AI 호출 실패 | 200 | `ai_status: "failed"` | "코드 분석으로 대체됨" 배지 + 경고 알림 |
| AI 응답 JSON 파싱 실패 | 200 | `ai_status: "failed"` | 동일 (파이프라인에서 조용히 폴백) |
| 응답 지연 45초 초과 | — | — | `AbortController` 로 중단 후 "응답 시간이 초과되었습니다" |
| 네트워크 단절 | — | — | "서버에 연결하지 못했습니다. 네트워크 상태를 확인해주세요" |

**원칙: 모든 실패는 사용자가 알아볼 수 있는 한국어 문장으로 안내하며,
가능하면 기능이 축소된 상태라도 결과를 제공한다.** (무조건 죽지 않는다)

## 6. 보안 설계

| 항목 | 조치 |
| --- | --- |
| API 키 저장 | 코드·HTML 어디에도 없음. Vercel 환경변수 `OPENAI_API_KEY` 로만 주입 |
| 키 노출 방지 | `.env`, `.env.local`, `.vercel` 을 `.gitignore` 에 등록. 커밋된 예시 파일은 `.env.example` (값 없음) |
| 키 재발급 | 키가 노출되면 Vercel 대시보드에서 삭제·재생성하면 즉시 반영됨. 저장소 이력에 키가 없으므로 커밋 이력 정리 불필요 |
| XSS 방어 | 외부 API 데이터는 `escapeHtml()` 로 이스케이프 후 `innerHTML` 삽입 |
| 경로 탈출 방지 | `dev_server.py` 가 `..` 경로를 차단 (개발용 서버) |
| 에러 정보 노출 제한 | AI API 오류는 상태 코드만 서버 로그에 남기고, 사용자에게는 일반 메시지만 전달 |

## 7. 응답형 설계

| 화면 | 기준 | 주요 변화 |
| --- | --- | --- |
| 데스크톱 | > 768px | 카드 그리드 3열, 폼 2열, 내비게이션 우측 정렬 |
| 태블릿 | 768px 이하 | 카드 1열, 폼 1열, 내비게이션 두 번째 줄 |
| 모바일 | 480px 이하 | 여백·패딩 축소, 점수 원형 축소, 푸터 세로 배치 |

- 실측 확인: **1280×900 (데스크톱)**, **390×844 (모바일)** — 두 크기에서 가로 스크롤 없음 확인
- `prefers-reduced-motion` 을 존중해 애니메이션을 끔
- 키보드 포커스 표시(`:focus-visible`), `aria-label`, `aria-current`, `role="alert"` 적용

## 8. 기술적 한계 (정직한 고지)

1. **국내 공고 미포함** — 사용한 3개 API는 모두 해외 원격 공고 중심입니다. 국내 공고를 넣으려면 사람인/원티드 API 승인 절차가 별도로 필요합니다.
2. **캐시가 휘발적** — Vercel Serverless Functions의 메모리 캐시는 인스턴스 종료 시 사라집니다. "10분마다 갱신"이 아니라 "인스턴스 생존 중 재사용"입니다.
3. **비-IT 공고 혼재** — Arbeitnow 출처에 세차장·청소 등 일반 고용 공고가 섞여 있어, 코드 매칭에서 직군 적합도로 감점 처리합니다.
4. **추천은 참고용** — 실제 적합도를 보증하지 않으며, 지원 가능 여부는 공고 원문과 채용 담당자의 판단이 우선입니다.
5. **AI 판정은 확률적** — 같은 입력에도 모델 버전·온도에 따라 결과가 달라질 수 있습니다. 코드 사전 점수를 함께 표시하는 이유입니다.

## 9. 확장 계획

- 사람인/원티드 API 승인 후 `api/_lib/providers/` 에 새 어댑터 추가만 하면 되도록 인터페이스 통일
- 사용자 조건을 공고 목록에 URL 쿼리스트로 전달해 "공고 목록으로 이동" 기능
- 추천 결과 피드백(좋았어요/아니에요) 수집 및 가중치 학습
